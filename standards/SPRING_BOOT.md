# 선택형 Spring Boot 규칙

서버가 필요할 때만 사용하며 회사 프로젝트는 회사의 규칙을 우선 확인한다.
- Java/Spring Boot 버전과 Maven/Gradle을 명시하고 기존 Wrapper를 사용한다.
- 컨트롤러의 입력 검증, 서비스의 업무 규칙, 데이터 접근 책임을 분리하되 불필요한 계층은 만들지 않는다.
- 인증과 객체 단위 인가를 구분한다. 소유권·권한을 서버에서 검증한다.
- 트랜잭션 경계, 동시성, 중복 요청, 페이지네이션, 시간대, 오류 응답을 설계한다.
- 스키마 변경은 버전 관리된 마이그레이션으로 제공하고 데이터 손실과 롤백 가능성을 설명한다.
- 운영 비밀은 승인된 비밀 관리 수단으로 주입한다. 로그에 개인정보·토큰을 남기지 않는다.
- 선택한 도구에 따라 ./gradlew test 또는 ./mvnw test를 실행한다. DB·보안·API 계약은 관련 통합 테스트로 확인한다.
