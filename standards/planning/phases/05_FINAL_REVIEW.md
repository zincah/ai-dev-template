# Phase 5: Final Review & Handoff

## 목적과 입력

기획 문서를 검증하고 Codex로 전달한다. 현재 PLANNING_STATUS와 사용자 승인된 이전 단계 산출물을 확인한다. 이전 단계 승인이 없으면 단계 전환을 멈추고 필요한 결정을 정리한다.

## 검토 항목

- 문서 간 일관성
- 요구사항 누락
- 요구사항 충돌
- 기능 간 의존성
- MVP 범위
- 구현 가능성
- 데이터 요구사항
- 보안 및 개인정보
- 미확정 사항
- 개발 위험 요소

## 대화 운영

첫 질문 예시: “남은 위험과 미결정을 포함한 이 문서 버전을 Codex 설계 기준으로 승인하시나요?”
한 번에 하나의 주요 의사결정에 집중하고 대안·장단점을 제공한다. 사용자 확정, AI 제안, 미확정을 분리한다. [품질 규칙](../PLANNING_QUALITY.md)의 10개 항목을 검사한다. Critical 0건이 필수다. 해결되지 않은 Major는 사용자 위험 수용과 후속 조치를 기록한다. 승인 문서 버전·증거를 기록하고 Git 기준 커밋을 인계 시 전달한다.

## 산출물

PLANNING_REVIEW.md, HANDOFF.md. [템플릿 선택표](../PLANNING_WORKFLOW.md)를 사용한다. 문서 변경 후 상태 요약, 미결정, 현재/다음 작업을 갱신한다.

## 완료 조건과 승인

- [ ] 핵심 요구사항이 검증되었다
- [ ] 중요한 문서 간 모순이 해결되었다
- [ ] 미확정 사항이 명시되었다
- [ ] 사용자가 기획 결과를 승인했다
- [ ] Codex 전달 문서가 준비되었다

완료 조건을 확인하면 REVIEW로 둔다. 문서 버전과 결정 사항을 요약해 사용자 승인을 요청하고 명시적 승인 후에만 APPROVED로 기록한다. 미승인이면 다음 단계로 넘어가지 않는다. Phase 5의 마지막 승인 항목도 AI가 체크하지 않는다.
변경으로 완료 조건이 깨지면 영향받는 단계와 문서를 명시하고 재검토한다. [상태 운영 규칙](../PLANNING_STATUS_RULES.md)을 따른다.
