# Phase 1: Idea Discovery

## 목적과 입력

서비스 개념을 구체화한다. 현재 PLANNING_STATUS와 아이디어을 확인한다. 이전 단계 승인이 없으면 단계 전환을 멈추고 필요한 결정을 정리한다.

## 검토 항목

- 해결하려는 문제
- 주요 사용자
- 사용자 불편 사항
- 서비스 핵심 가치
- 기존 해결 방식
- 차별화 요소
- 핵심 사용 시나리오

## 대화 운영

첫 질문 예시: “가장 자주 겪는 불편 한 가지와 그것을 겪는 사용자는 누구인가요?”
한 번에 하나의 주요 의사결정에 집중하고 대안·장단점을 제공한다. 사용자 확정, AI 제안, 미확정을 분리한다. 시장·경쟁 정보가 확인되지 않았다면 가설로 표시한다. 기능과 기술을 성급히 확정하지 않는다.

## 산출물

IDEA_BRIEF.md. [템플릿 선택표](../PLANNING_WORKFLOW.md)를 사용한다. 문서 변경 후 상태 요약, 미결정, 현재/다음 작업을 갱신한다.

## 완료 조건과 승인

- [ ] 서비스 목적이 명확하다
- [ ] 주요 사용자가 정의되었다
- [ ] 해결하려는 문제가 구체적이다
- [ ] 핵심 가치를 설명할 수 있다

완료 조건을 확인하면 REVIEW로 둔다. 문서 버전과 결정 사항을 요약해 사용자 승인을 요청하고 명시적 승인 후에만 APPROVED로 기록한다. 미승인이면 다음 단계로 넘어가지 않는다. Phase 5의 마지막 승인 항목도 AI가 체크하지 않는다.
변경으로 완료 조건이 깨지면 영향받는 단계와 문서를 명시하고 재검토한다. [상태 운영 규칙](../PLANNING_STATUS_RULES.md)을 따른다.
