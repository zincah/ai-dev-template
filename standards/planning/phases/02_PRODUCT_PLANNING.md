# Phase 2: Product Planning

## 목적과 입력

전체 기능과 운영 방향을 정의한다. 현재 PLANNING_STATUS와 사용자 승인된 이전 단계 산출물을 확인한다. 이전 단계 승인이 없으면 단계 전환을 멈추고 필요한 결정을 정리한다.

## 검토 항목

- 핵심 기능
- 부가 기능
- 사용자 역할
- 서비스 운영 방식
- 데이터 관리 방식
- 외부 서비스 연동
- 플랫폼 요구사항
- 주요 제약사항

## 대화 운영

첫 질문 예시: “핵심 가치를 제공하는 데 꼭 필요한 기능은 무엇인가요?”
한 번에 하나의 주요 의사결정에 집중하고 대안·장단점을 제공한다. 사용자 확정, AI 제안, 미확정을 분리한다. 상세 입력 규칙은 Phase 3에 위임한다. 기능 후보에 제품 수준 REQ ID를 유지할 수 있으며 FR로 연결한다.

## 산출물

PRD.md. [템플릿 선택표](../PLANNING_WORKFLOW.md)를 사용한다. 문서 변경 후 상태 요약, 미결정, 현재/다음 작업을 갱신한다.

## 완료 조건과 승인

- [ ] 주요 기능이 정의되었다
- [ ] 기능 간 관계가 정리되었다
- [ ] 서비스 범위가 명확하다
- [ ] 주요 제약사항이 확인되었다

완료 조건을 확인하면 REVIEW로 둔다. 문서 버전과 결정 사항을 요약해 사용자 승인을 요청하고 명시적 승인 후에만 APPROVED로 기록한다. 미승인이면 다음 단계로 넘어가지 않는다. Phase 5의 마지막 승인 항목도 AI가 체크하지 않는다.
변경으로 완료 조건이 깨지면 영향받는 단계와 문서를 명시하고 재검토한다. [상태 운영 규칙](../PLANNING_STATUS_RULES.md)을 따른다.
