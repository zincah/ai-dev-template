# Phase 4: UX Specification

## 목적과 입력

사용자가 앱을 사용하는 흐름과 화면 상태를 정의한다. 현재 PLANNING_STATUS와 사용자 승인된 이전 단계 산출물을 확인한다. 이전 단계 승인이 없으면 단계 전환을 멈추고 필요한 결정을 정리한다.

## 검토 항목

- 화면 목록
- 화면별 역할
- 사용자 이동 흐름
- UI 구성 요소
- 입력 및 이벤트
- 로딩 상태
- 오류 상태
- 빈 데이터 상태
- 사용자 피드백

## 대화 운영

첫 질문 예시: “사용자가 핵심 작업을 시작해서 끝낼 때 어떤 순서로 이동하나요?”
한 번에 하나의 주요 의사결정에 집중하고 대안·장단점을 제공한다. 사용자 확정, AI 제안, 미확정을 분리한다. SCR ID와 FR ID를 연결하고 FLOW 시나리오를 순서대로 검토한다. 서버 단독은 자체 화면 해당 없음의 근거와 API 소비자 흐름을 남긴다. UI가 없다는 이유로 예외 흐름 검토를 생략하지 않는다.

## 산출물

USER_FLOW.md, SCREEN_SPEC.md. [템플릿 선택표](../PLANNING_WORKFLOW.md)를 사용한다. 문서 변경 후 상태 요약, 미결정, 현재/다음 작업을 갱신한다.

## 완료 조건과 승인

- [ ] MVP 기능에 필요한 화면이 정의되었다
- [ ] 화면 간 이동 흐름이 명확하다
- [ ] 주요 사용자 시나리오가 검증되었다
- [ ] 오류 및 빈 상태가 정의되었다

완료 조건을 확인하면 REVIEW로 둔다. 문서 버전과 결정 사항을 요약해 사용자 승인을 요청하고 명시적 승인 후에만 APPROVED로 기록한다. 미승인이면 다음 단계로 넘어가지 않는다. Phase 5의 마지막 승인 항목도 AI가 체크하지 않는다.
변경으로 완료 조건이 깨지면 영향받는 단계와 문서를 명시하고 재검토한다. [상태 운영 규칙](../PLANNING_STATUS_RULES.md)을 따른다.
