# 기획 품질 검증

Phase 5에서 아래 10개 항목을 통과/실패/해당 없음으로 기록하고 근거 문서·ID를 남긴다. 해당 없음에는 이유가 필요하다. [검토 프롬프트](https://github.com/zincah/ai-dev-template/blob/main/prompts/chatgpt/PLANNING_REVIEW.md)를 사용하고 결과는 앱의 PLANNING_REVIEW.md에 기록한다.

1. 모든 MVP 기능에 FR(기존 앱은 대응표의 REQ) ID가 있는가?
2. 모든 핵심 기능에 검증 가능한 완료 조건이 있는가?
3. FR과 SCR이 연결되고 서버 단독은 해당 없음의 근거와 소비자 흐름이 있는가?
4. 정상 흐름과 예외 흐름이 정의되어 있는가?
5. 요구사항 간 충돌이 해결되었는가?
6. 중요한 미확정 사항의 영향·담당자·결정 시점이 명확한가?
7. 데이터 저장·조회·삭제·보관 요구사항이 충분한가?
8. 권한·보안·개인정보 요구사항이 검토되었는가?
9. MVP 범위가 핵심 가치에 집중하고 과도하지 않은가?
10. Codex가 추측 없이 설계를 시작할 만큼 명세가 충분한가?

## 심각도와 완료 조건

| 등급 | 기준 | 처리 |
|---|---|---|
| Critical | 핵심 기능이 모순되거나 명세 부족으로 설계 불가, 중대한 권한·데이터 위험 | 해결 전 완료·Phase 5 APPROVED 금지, BLOCKED 기록 |
| Major | 핵심 설계에 영향을 주는 예외·의존성·측정 기준 누락 | 해결 또는 명시적인 사용자 위험 수용, 담당자·기한·영향 기록 |
| Minor | 설계 진행을 막지 않는 표현·참조·편의 개선 | 후속 조치와 담당자 기록 |

각 지적은 REV ID, 근거, 재현/문제 조건, 영향, 권장 조치, 담당자, 상태로 관리한다. 위험 수용은 문제 해결로 위장하지 않는다. Critical에는 위험 수용만으로 완료하는 예외를 두지 않는다.
검토 결과가 통과해도 사용자 승인 없이는 APPROVED가 아니다. 승인 버전 이후 변경은 영향 분석과 재검토를 수행한다. 수정한 지적을 다시 확인하고 최종 잔여 위험을 HANDOFF에 연결한다.
