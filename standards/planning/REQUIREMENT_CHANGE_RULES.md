# 요구사항 변경 운영

변경 요청을 CHG ID로 REQUIREMENT_CHANGES.md에 기록한다. 초안의 문구 수정은 버전 갱신으로 처리할 수 있지만 확정 요구사항·MVP·권한·데이터 정책 변경은 반드시 변경 이력을 남긴다.

1. PROPOSED: 기존/제안 요구사항과 이유를 기록한다. 확정 문서는 변경하지 않는다.
2. UNDER_REVIEW: FR/NFR, FLOW/SCR, 데이터, PRD/MVP, 아키텍처·DB·API·TASK·테스트 영향을 분석하고 비용·위험·대안을 제시한다. 개발 중이라면 구현된 부분과 재작업 범위를 확인한다.
3. APPROVED 또는 REJECTED: 사용자가 해당 변경안에 대해 명시적으로 결정한 날짜·증거를 기록한다. 침묵은 승인으로 처리하지 않는다. 재제안은 새 CHG로 이전 항목을 참조한다.
4. APPLIED: APPROVED인 변경만 확정 문서에 반영한다. 변경한 파일·버전·관련 커밋과 검증 결과를 기록하고 참조 관계를 점검한 뒤 APPLIED로 전환한다. 부분 반영은 APPROVED 상태로 남기고 남은 작업을 적는다.

APPLIED는 단계 재승인과 다르다. 영향받은 APPROVED 단계는 이전 승인 이력을 보존하고 REVIEW로 돌린 뒤 사용자 재승인을 받는다. Critical이 발견되면 BLOCKED로 둔다. 사용자 승인을 받은 변경이라도 개발·기획을 완료했다고 자동 판단하지 않는다.
ID를 재사용하거나 조용히 삭제하지 않는다. 폐기 FR은 상태·대체 ID를 남긴다. PLANNING_STATUS에는 변경 요약·영향 단계·다음 작업만 기록한다.
