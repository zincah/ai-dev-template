# Flutter 기본 규칙

권장값이며 기존 프로젝트 관례와 요구사항을 먼저 확인한다.
- iOS와 Android의 권한, 뒤로가기, 키보드, 안전 영역, 글자 확대를 확인한다.
- 기능별 구조를 기본 후보로 두고 작은 앱에 불필요한 계층을 강제하지 않는다. UI에 네트워크·영속화 로직을 집중시키지 않는다.
- 상태관리와 라우터는 프로젝트별로 선택한다. 로딩/성공/빈 상태/오류/재시도를 명시한다.
- 오프라인 지원, 동기화 충돌, 캐시, 토큰 저장, 앱 복귀 동작은 필요한 경우 설계한다.
- 환경별 URL과 설정을 분리한다. 앱에 포함된 값은 추출 가능하므로 서버 비밀을 넣지 않는다.
- 변경 범위에 맞춰 dart format, flutter analyze, flutter test를 실행한다. 핵심 사용자 흐름은 통합 테스트 또는 기기 확인으로 검증한다.
- iOS/Android 빌드·기기 테스트 여부를 각각 기록한다. macOS 도구·서명·기기가 없으면 미검증으로 명시한다.
