# 기획 최종 검토

## 문서 목적

Codex 인계 전에 품질과 잔여 위험을 검증한다.

## 작성 방법

실제 앱 docs/PLANNING_REVIEW.md로 복사한다. {…}를 실제 내용으로 채우고 미결정은 Q ID로 표시한다. 품질 규칙 (`standards/planning/PLANNING_QUALITY.md`)의 모든 항목을 평가한다. 문서를 읽지 못하면 미검토로 기록하고 통과를 주장하지 않는다.
예시는 합성 데이터이며 요구사항으로 자동 채택하지 않는다. 문서 버전·작성자·갱신일을 기록한다.

## 필수 작성 항목

- 검토일 / 검토자 / 문서 버전·대상 Git 커밋: {{내용}}
- 입력 문서 목록 / 접근하지 못한 문서: {{내용}}
- 종합 결과: {{수정 필요·차단·승인 대기·사용자 승인}}
- 미해결 Critical/Major/Minor 건수: {{건수}}

## 작성 예시

REV-001 Major: FR-001의 중복 요청 처리 규칙이 없어 모바일 재시도 때 데이터가 중복될 수 있다. 처리 규칙과 API 계약 요구를 보완하고 재검증한다. 검토 지적이 해결되어도 사용자 승인 전에는 “승인 대기”로 유지한다.
