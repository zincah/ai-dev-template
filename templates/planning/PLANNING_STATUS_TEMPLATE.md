# 기획 진행 상태

## 문서 목적

현재 상태와 다음 행동의 기준이며 상세 요구사항을 중복 저장하지 않는다.

## 작성 방법

실제 앱 docs/PLANNING_STATUS.md로 복사한다. {…}를 실제 내용으로 채우고 미결정은 Q ID로 표시한다. 상태 운영 규칙 (`standards/planning/PLANNING_STATUS_RULES.md`)에 따라 갱신한다. 초기 예시의 상태를 실제 프로젝트 승인으로 사용하지 않는다.
예시는 합성 데이터이며 요구사항으로 자동 채택하지 않는다. 문서 버전·작성자·갱신일을 기록한다.

### 단계별 진행 상태

상태: NOT_STARTED / IN_PROGRESS / BLOCKED / REVIEW / APPROVED. 승인 증거에는 승인자·날짜·문서 버전·대화 발췌 또는 링크를 포함한다.

| 단계 | 현재 상태 | 완료된 작업 | 남은 작업 | 산출물·버전 | 사용자 승인 여부·증거 |
|---|---|---|---|---|---|
| Phase 1: Idea Discovery | NOT_STARTED | 없음 | 브리프 작성 | IDEA_BRIEF.md | 미승인 |
| Phase 2: Product Planning | NOT_STARTED | 없음 | 제품 기획 | PRD.md | 미승인 |
| Phase 3: Requirements Definition | NOT_STARTED | 없음 | FR/NFR/MVP 확정 | FUNCTIONAL_REQUIREMENTS.md, NON_FUNCTIONAL_REQUIREMENTS.md, MVP_SCOPE.md | 미승인 |
| Phase 4: UX Specification | NOT_STARTED | 없음 | 흐름·화면 검증 | USER_FLOW.md, SCREEN_SPEC.md | 미승인 |
| Phase 5: Final Review & Handoff | NOT_STARTED | 없음 | 검토·인계 준비 | PLANNING_REVIEW.md, HANDOFF.md | 미승인 |

## 작성 예시

새 습관 앱의 아이디어 설명을 확인했다면 Phase 1과 전체 상태를 IN_PROGRESS로 갱신한다. Phase 1 문서 초안이 완성되면 REVIEW로 두고 승인 대기한다. “브리프 v0.1 승인”을 사용자가 명시한 뒤에만 해당 단계 APPROVED와 증거를 기록한다. 아직 시작하지 않은 나머지 단계는 NOT_STARTED다.

## 검증 체크리스트

- [ ] 5단계 상태·산출물·승인 정보가 모두 있는가
- [ ] 현재 단계와 전체 상태가 전환 규칙에 맞는가
- [ ] 미결정·다음 작업·CHG 상세 경로가 있는가
- [ ] APPROVED에 해당 버전의 사용자 승인 증거가 있는가
