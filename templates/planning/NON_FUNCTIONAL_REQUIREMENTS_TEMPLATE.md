# 비기능 요구사항

## 문서 목적

품질·운영·보안 요구사항의 단일 원본이다.

## 작성 방법

실제 앱 docs/NON_FUNCTIONAL_REQUIREMENTS.md로 복사한다. {…}를 실제 내용으로 채우고 미결정은 Q ID로 표시한다. NFR마다 대상·환경·측정 방법·합격 기준을 적고 임의 수치를 사용자 확정으로 표시하지 않는다.
예시는 합성 데이터이며 요구사항으로 자동 채택하지 않는다. 문서 버전·작성자·갱신일을 기록한다.

## 필수 작성 항목

- 문서 버전 / 작성자 / 갱신일: {{내용}}
- NFR ID / 이름 / 상태 / 우선순위 / 연결 FR: {{내용}}
- 분류: 성능·접근성·지원 OS·안정성·보안·개인정보·운영: {{내용}}
- 적용 대상 / 환경·부하 / 요구사항 / 이유: {{내용}}
- 측정 방법 / 완료 조건 / 검증 책임자: {{내용}}
- 데이터 수집 목적·동의·보관 기간·삭제·로그 정책: {{내용}}
- 권한·비밀 저장 / 플랫폼 차이 / 외부 의존성: {{내용}}
- 미결정 Q / 승인 버전 / 변경 CHG: {{내용}}

## 작성 예시

NFR-001 글자 확대 지원 / 제안 / Must / FR-001. Flutter iOS·Android에서 시스템 글자 크기 200%로 SCR-001의 핵심 입력과 저장 동작을 사용할 수 있어야 한다. 양 플랫폼에서 확대·포커스·가로 화면 확인으로 검증한다.
서버 단독 예: NFR-002 승인된 합성 부하 조건에서 기록 조회 지연의 p95 목표와 측정 방법을 정한다. 수치와 환경은 사용자 결정 전 미확정으로 남긴다.

## 검증 체크리스트

- [ ] 수치·환경·측정 방법·합격 기준이 정의되었는가
- [ ] 보안·개인정보·지원 플랫폼을 검토했는가
- [ ] 가정·미결정·사용자 확정이 구분되는가
