# 서비스 아이디어 브리프

## 문서 목적

Phase 1에서 문제·사용자·가치를 정의한다.

## 작성 방법

실제 앱 docs/IDEA_BRIEF.md로 복사한다. {…}를 실제 내용으로 채우고 미결정은 Q ID로 표시한다. 기능 목록을 앞세우지 말고 사용자 상황으로 설명한다.
예시는 합성 데이터이며 요구사항으로 자동 채택하지 않는다. 문서 버전·작성자·갱신일을 기록한다.

## 필수 작성 항목

- 프로젝트명 / 설명 / 버전 / 작성자 / 날짜: {{내용}}
- 해결하려는 문제와 관찰 근거: {{내용}}
- 주요 사용자와 사용 상황: {{내용}}
- 사용자 불편 사항 / 기존 해결 방식: {{내용}}
- 핵심 가치 / 차별화 가설: {{내용}}
- 핵심 사용 시나리오: {{내용}}
- 가정·미확정 Q ID / 승인 버전·증거: {{내용}}

## 작성 예시

개인 습관 기록 앱: 사용자가 운동 여부를 메모장에 흩어 기록해 일주일의 실천을 파악하기 어렵다. 오늘의 실천을 한 번에 기록하고 주간 현황을 확인하는 것이 핵심 가치다. 차별화는 가설이며 사용자 확인 전 확정하지 않는다.
Spring Boot 단독 서비스라면 API 소비자와 그 업무 불편을 주요 사용자·상황으로 적는다.

## 검증 체크리스트

- [ ] 문제·주요 사용자·서비스 목적이 구체적인가
- [ ] 핵심 가치를 설명할 수 있는가
- [ ] 가설과 확정이 구분되는가
