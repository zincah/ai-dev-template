# 기능 요구사항

## 문서 목적

상세 기능 요구사항의 단일 원본이다.

## 작성 방법

실제 앱 docs/FUNCTIONAL_REQUIREMENTS.md로 복사한다. {…}를 실제 내용으로 채우고 미결정은 Q ID로 표시한다. FR마다 아래 항목을 반복한다. PRD 제품 REQ와 연결하며 우선순위는 Must/Should/Could로 작성한다. MVP 포함 여부는 MVP_SCOPE를 참조한다.
예시는 합성 데이터이며 요구사항으로 자동 채택하지 않는다. 문서 버전·작성자·갱신일을 기록한다.

## 필수 작성 항목

- 문서 버전 / 작성자 / 갱신일: {{내용}}
- 요구사항 ID / 기능명 / 상태(제안·확정·폐기): FR-{{번호}} / {{내용}}
- 설명 / 사용자 가치 / 제품 REQ ID: {{내용}}
- 우선순위 / 근거: {{내용}}
- 입력값: 이름·타입·필수·허용 범위·기본값: {{내용}}
- 처리 규칙 / 사전 조건 / 저장·조회·삭제 대상: {{내용}}
- 정상 처리 / 결과: {{내용}}
- 예외 처리: 검증 실패·권한·네트워크·중복 요청: {{내용}}
- 권한 / 소유권 / 관련 NFR: {{내용}}
- 완료 조건: Given / When / Then 및 검증 방법: {{내용}}
- 관련 화면 SCR / 흐름 FLOW: {{내용 또는 해당 없음과 이유}}
- 의존 기능 FR / 미확정 Q / 관련 변경 CHG / 승인 버전: {{내용}}

## 작성 예시

FR-001 오늘 실천 기록 / 제안 / Must. 입력은 날짜와 실천 여부이며 날짜 형식을 검증한다. 같은 날짜는 하나의 기록을 갱신한다. 정상 시 저장 결과를 보여주고 실패 시 재시도와 입력값을 보존한다. SCR-001, FLOW-001과 연결한다. 완료 조건: 오늘 기록이 없을 때 실천 완료를 저장하면 오늘의 기록 한 건이 보이며 재요청해도 중복되지 않는다.
서버 사용 시 인증 사용자 본인의 기록만 갱신할 수 있고 다른 사용자의 기록 요청은 거부한다. 서버 미사용 시 서버 관련 조건은 해당 없음으로 확정한다.

## 검증 체크리스트

- [ ] 입력·저장·권한·정상/예외 처리와 완료 조건이 명확한가
- [ ] FR 의존성·SCR·FLOW 참조가 유효한가
